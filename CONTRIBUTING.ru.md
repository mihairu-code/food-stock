# Как вносить изменения

Заметки для того, кто будет трогать этот код следующим, — в основном для меня через
месяц. [In English](CONTRIBUTING.md)

## Перед тем как сказать «готово»

```bash
npm test
npm run lint
npm run build
```

Все три. Потом — проверить изменение в браузере в демо-режиме (без ключей Supabase,
данные в `localStorage`). Если задеты шторки, формы или жесты — на телефоне, приложением
с экрана «Домой»: см. [заметки про iPhone](docs/ru/ios-notes.md).

## Код

- **Слои (FSD).** Слой импортирует только нижние, слайсы одного слоя друг друга не знают,
  снаружи в слайс заходят через его `index.ts`. Нарушение ловит
  `src/app/fsdBoundaries.test.ts`.
- **Один файл — один компонент.** Хуки и функции — в `model/` или `lib/`.
- **Импорты от корня через `@/`** и через публичный API слайса (`@/entities/product`);
  внутри слайса — относительные.
- **Переиспользуй, а не верстай заново.** Форма в шторке — `FormSheet`; название
  с иконкой — `NameIconFields`; выбор раздела — `SectionPicker`; строка настроек —
  `SettingRow` / `SettingSelect` / `SettingToggle`; перетаскиваемая строка — `SortableRow`;
  свайп удаления — `SwipeRow`. Один и тот же элемент должен выглядеть одинаково везде.
- **Шторки** рисует только `SheetHost`. Экран вызывает `openSheet({ type: … })`.
  Новая шторка: компонент в `features/…`, вариант в `SheetRequest`
  (`shared/ui/sheet/sheetStore.ts`), строка в `app/sheets/SheetHost.tsx`.
- **Тост** — `notify('ключ', параметры)`; это функция, не хук.
- **Мутации** описываются в `entities/*/api` вместе с тостом об ошибке и перечитыванием
  кэша. Компонент только вызывает `mutate`. Данные дома правятся через
  `useHomeMutation` (оптимистично, строго по очереди).
- **Новый метод хранилища** — в `shared/api/backend.ts`, обеих реализациях и тестах
  (`src/app/homeFlows.test.ts`).
- **Стили** — файл рядом со своим слоем, подключение — в `app/styles/index.css`.
  Размеры — `rem` по шкалам из `tokens.css`; `px` — только рамки, тени, обводки.
- **Тексты** — ключ в `ru.ts` и те же ключи в трёх остальных словарях; иначе упадёт
  `i18n.test.ts`.
- **Цвета** — только через переменные (`--accent`, `--paper`, `--ink`…); тема и акцент
  задаются атрибутами `data-theme` и `data-accent` на `<html>`.
- Комментарии объясняют «почему», а не «что». Без `console.log`.

## Как оформлен код

Форматтера нет — оформление держится на соглашениях ниже. Новый код пишется так же,
как соседний в том же слое.

- **Внешний вид:** 2 пробела, без точек с запятой, одинарные кавычки, запятая после
  последнего элемента многострочных списков, скобки у параметра стрелочной функции.
- **Экспорты только именованные.** Единственное исключение — `App` для `main.tsx`.
  Строка списка в `memo` — `export const ProductRow = memo(function ProductRow(…) {…})`,
  с именем внутри, чтобы оно было видно в React DevTools.
- **Пропсы:** больше трёх или с пояснениями — `interface …Props` прямо над компонентом,
  пояснение — `/** … */` над полем; два-три очевидных — тип прямо в параметрах.
  Необязательный флаг — со значением по умолчанию в деструктуризации.
- **Типы:** `import type` (включён `verbatimModuleSyntax`), без `enum` и `namespace` —
  объединения строк и `as const`. Поля записей из базы — `snake_case`, как в таблицах;
  всё остальное — `camelCase`.
- **Константы модуля** — `UPPER_SNAKE_CASE` в начале файла, с комментарием, откуда число.
- **Имена файлов:** компонент — `PascalCase.tsx` по имени компонента; хук — `useX.ts`;
  остальные модули — `camelCase.ts` по смыслу; стили — `camelCase.css` рядом; тест —
  `имя.test.ts` рядом с модулем. В `api/` сущности — один файл `<сущность>Api.ts` со
  всеми её запросами и мутациями.
- **Папки слайса:** `ui/` — компоненты, `model/` — правила и хуки состояния, `api/` —
  запросы и мутации, `lib/` — мелкие помощники. В `index.ts` — только то, что нужно снаружи.
- **Состояние элемента в разметке — атрибутом `data-*`**, а не классом: `data-open`,
  `data-missing`. Класс-модификатор — только для постоянного вида: `btn subtle`.
- **Кнопки:** у каждой `type="button"`; у кнопки с одной иконкой — `aria-label` из
  словаря; иконки — `lucide-react`, декоративные — `aria-hidden`.
- **`useEffect` — только для связи с внешним миром:** DOM, подписки, таймеры, хранилище.
  Производное значение считается в рендере.
- **`localStorage`:** ключ — константа в начале модуля вида `'home-stock:имя'`; чтение и
  запись — в `try`: в приватном режиме хранилище бросает исключение.
- **Цвета** — только через переменные, в том числе одинаковый в обеих темах (`--white`).
  Прямой цвет — только в тенях и в `::backdrop` (старые iOS не видят там переменных
  страницы).

## Что нельзя ломать

Старая версия ещё какое-то время работает на телефонах с той же базой.

- **Миграции только добавляют.** Не удаляй и не переименовывай таблицы, столбцы,
  функции; не меняй параметры существующих RPC — заведи новую функцию.
- **Сначала миграция, потом выкладка.** Приложение запрашивает новые столбцы.
- **Не переименовывай ключи `home-stock:*`** в `localStorage` (сессия, дом, имя, язык,
  тема, акцент, подсказки).
- **Никакого `React.lazy` и динамического `import()`** — см.
  [решение 0004](docs/ru/decisions/0004-safe-updates.md).
- **Меняешь форму данных дома** — увеличь `VERSION` в `shared/api/snapshot.ts`.
- **Доступ к данным — только через RLS.** Новая таблица без политики — дыра.

## Ветки и выкладка

Vercel собирает приложение прямо из GitHub.

- **Работа — в ветке фичи:** `feat/<фича>`, `refactor/<что>`. Готовая фича сливается
  в `main`. Вернулся к той же фиче с исправлениями — новая ветка с тем же названием
  и следующей версией: `feat/drag-and-drop-v2`, потом `-v3`.
- **У каждой ветки, кроме `main`, есть превью.** У превью нет ключей Supabase, поэтому
  оно работает в демо-режиме и настоящую базу не трогает.
- **Пуш в `main` — это выкладка на боевой сайт.** С миграцией порядок такой: ветка →
  проверка на превью → миграция к базе → слияние в `main`.
