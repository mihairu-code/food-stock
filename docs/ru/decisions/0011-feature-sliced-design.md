# 0011. Структура по Feature-Sliced Design

**Статус:** принято · ноябрь 2026

## Контекст

За две недели код вырос до сотни с лишним файлов в папках по типу: `components`,
`screens`, `sheets`, `data/hooks`, `lib`, `domain`. Чтобы поправить, например, покупку
ручной позиции, надо открыть пять папок. В `components` вперемешку лежат кнопка-строка
настроек и галочка «держать дома постоянно», которая знает про продукт. Кто кого может
импортировать — никак не ограничено, и `lib` уже начал тянуть данные.

## Варианты

- **Оставить по типам, навести порядок внутри.** Дёшево, но проблема «кто кого знает»
  остаётся.
- **По экранам (`home/`, `shopping/`, `settings/`), общее — в `common/`.** Хорошо для
  экранов, но шторки и сущности используются с нескольких экранов, и `common/` быстро
  становится новой свалкой.
- **Feature-Sliced Design.** Слои `app → pages → widgets → features → entities → shared`,
  слой импортирует только нижние, слайсы одного слоя друг друга не знают, наружу — только
  через `index.ts`. Правила известные, их легко проверить автоматически.

## Решение

FSD:

- `shared` — то, что не знает о продуктах и доме: API-клиент и кэш, i18n, мелкие
  библиотеки, общие элементы интерфейса, шторки как механизм;
- `entities` — продукт, раздел, ручная покупка, список покупок, участник, приглашение,
  дом: их запросы, мутации, правила и маленькие элементы;
- `features` — формы в шторках: добавить продукт, купить позицию, вступить в дом…;
- `widgets` — шапка и нижние вкладки;
- `pages` — экраны;
- `app` — запуск, провайдеры, маршруты, каркас и `SheetHost`.

Нарушение границ ловит тест `fsdBoundaries.test.ts`: импорт вверх, между слайсами одного
слоя и мимо `index.ts` слайса.

Переезд — тремя шагами, чтобы каждый шаг собирался: сначала `shared` и `entities`, потом
`features`, `widgets` и `pages`, потом `app`, публичные API слайсов и переименования.

## Последствия

- Больше папок и `index.ts`, зато понятно, где что искать и что можно трогать.
- Слайс — граница: если двум фичам нужно общее, оно спускается в `entities` или `shared`.
- Названия по смыслу в проекте (`saveProduct`, `deleteSectionNow`), а не общие
  (`submit`, `remove`).
