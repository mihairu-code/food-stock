# 0018. Третий цвет точки и режим «не только цветом»

**Статус:** принято · ноябрь 2026

## Контекст

У продукта две независимые отметки: «есть дома» и «в покупках»
([решение 0006](0006-independent-stock-and-to-buy.md)). Точка на иконке показывала только
первую: есть — зелёная (в светлой теме её нет), закончилось — красная. Продукт, который ещё
есть, но лежит в покупках, выглядел как обычный продукт в наличии. А в магазине важно
отличать «брать обязательно» (закончилось) от «по желанию» (ещё есть).

Второе: красный, оранжевый и зелёный — ровно те цвета, которые хуже всего различают люди
с нарушениями цветового зрения. Система не сообщает вебу о таких нарушениях, угадать их
нельзя.

## Варианты

- **Третье состояние по нажатию на иконку** (есть → мало → закончилось). Нажатие
  перестаёт быть простым переключателем, а «мало» не значит «купить».
- **Долгое нажатие** для «заканчивается». Жест никто не найдёт, на iPhone он конфликтует
  с перетаскиванием.
- **Отдельный флаг в базе.** Миграция и ещё одна отметка, которую нужно держать в
  согласии с двумя первыми.
- **Отдельные палитры под каждый тип нарушения.** Человеку пришлось бы знать свой
  диагноз, а нам — поддерживать четыре набора цветов.
- **Вывести третье состояние из двух отметок, а для различения добавить форму.**

## Решение

Состояние точки выводится из двух существующих полей — `stockState(product)` в
`entities/product/model/stockRules.ts`:

| Состояние | Условие | Точка | Подпись на «Доме» |
|---|---|---|---|
| `in` | есть, не в покупках | светлая тема — нет, тёмная — зелёная | «Постоянный продукт» / «Разово» |
| `low` | есть и в покупках | оранжевая | «Ещё есть · в покупках» |
| `out` | закончилось | красная, иконка серая | «Закончилось» / «Закончилось · в покупках» |

Внутреннее имя `low` — только в коде; слова «мало» в интерфейсе нет: плюс жмут и про
запас, и по акции, и для конкретного блюда. Строка списка получает состояние атрибутом
`data-stock`, в покупках — то же, у ручных позиций атрибута и точки нет.

Настройка «Различать не только цветом» (Настройки → «Приложение», по умолчанию выключена)
ставит `data-color-safe` на `<html>`. В этом режиме точка крупнее, «ещё есть, в покупках» —
закрашенный наполовину круг с кольцом, «закончилось» — сплошной круг с чертой, как знак
«нет»; цвета — пара из палитры Okabe–Ito (небесно-голубой и киноварь), различимая при
любом нарушении. Форма — только CSS. Ключ `home-stock:color-safe` читает и скрипт в
`index.html`, чтобы точки не перерисовывались при запуске.

Скринридер узнаёт состояние из подписи и `aria-label` главной кнопки строки, не из цвета.

## Последствия

- Данные, правила наличия и триггер `products_sync_to_buy` не изменились, миграции нет.
- Новое состояние точки — новое значение `stockState` и правило в `productStockIcon.css`
  для обоих режимов.
- Цвета точек — отдельные токены (`--stock-in`, `--stock-low`, `--stock-out` и `*-safe`);
  акценты, удаление и ошибки режим не трогает.
- Поменяли скрипт в `index.html` — поменяйте его хеш в `vercel.json` (это проверяет тест).
