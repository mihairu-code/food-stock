# 0003. Анонимные пользователи вместо регистрации

**Статус:** принято · ноябрь 2026

## Контекст

В v0.1 вход по коду из письма. На практике:

- на телефоне это переключиться в почту, найти письмо, скопировать код, вернуться;
- встроенная почта Supabase шлёт письма только участникам организации, для всех
  остальных нужен свой SMTP;
- приглашение по почте работает, только когда человек сам войдёт с этим адресом.

Для домашнего списка на 2–4 человека это слишком тяжёлый порог.

## Варианты

- **Оставить почту и подключить SMTP (Resend и т. п.).** Чинит доставку, но не
  неудобство на телефоне.
- **Общий секретный код дома.** Просто, но код живёт вечно и утекает навсегда.
- **Анонимный пользователь Supabase + ссылка-приглашение.** При первом запуске
  незаметно создаётся пользователь (`signInAnonymously`) и дом. Второго человека зовут
  ссылкой.

## Решение

Анонимные пользователи и одноразовые ссылки:

- у анонимного пользователя есть свой `auth.uid()`, так что все политики RLS остаются
  как были;
- ссылка одноразовая и живёт 7 дней, в базе хранится только хеш токена — прочитать
  готовую ссылку из таблицы нельзя, её показывают один раз при создании;
- вместо почты у участника необязательное имя;
- пустой дом, созданный автоматически при первом запуске, удаляется, когда человек
  вступает в чужой, — иначе у каждого приглашённого висел бы лишний пустой дом.

## Последствия

- Пользователь живёт в хранилище браузера. Почистил данные сайта или сменил телефон —
  для системы это новый человек. Это лечится аккаунтом, который можно привязать позже.
- На iPhone у Safari и у приложения на экране «Домой» раздельные хранилища: ссылка из
  мессенджера открывается в Safari. Поэтому в настройках нужна кнопка «Присоединиться
  по ссылке», куда ссылку можно вставить.
- Анонимный вход позволяет кому угодно создавать пользователей в проекте. Supabase
  ограничивает частоту по адресу; для публичного запуска понадобится капча.
