# v1.3.2 — A splash instead of a white screen

**November 2026**

## What's new for people

- **On a slow network, the first launch shows a loading picture instead of a white
  screen.** While the app downloads (a few seconds on 3G), the screen shows one of the
  three pictures. It doesn't disappear or blink after that: the app's own loading screen
  carries on in the same place and adds the text below.
- **The loading picture is random every time**: the fridge, the shelves or the shopping
  list, and never the same one twice in a row. Each place used to have its own.
- In the dark theme the page is dark from the very first moment, with no white flash.

## What changed in the code

- `index.html` has an inline style with the theme background (the `--bg` colours from
  `tokens.css`) and a splash inside `#root`: all three `LoadingPicture` pictures, checked
  by `bootSplash.test.ts`. The theme script picks one at random and writes it to
  `data-boot-picture` on `<html>`; `statusNote.css` hides the others. The splash stays
  hidden until the app styles arrive (`.boot`). React replaces it with its first screen.
- `StatusNote` takes `loading` without a picture kind. A full-screen note (launch,
  merging) uses the splash picture (`bootLoadingKind`); the others pick a new random one,
  different from the last (`nextLoadingKind` in `shared/lib/loadingKind.ts`).
- A full-screen loading note (`StatusNote fullscreen`) that appears more than 300 ms
  after the page started loading shows at once (`data-instant`): it replaces the splash
  or the same note of another step, and the pause would hide the fridge. Loading inside
  Home and Shopping still waits 300 ms.
- The theme script changed, so the hash in `vercel.json` is updated; CSP allows inline
  styles.
- The dictionaries weren't split: decision 0004 forbids dynamic `import()`, and the extra
  request at launch on 3G would eat the gain (about 20 KB).
