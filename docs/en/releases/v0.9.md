# v0.9 — New structure, editing products

**November 17, 2026**

## What's new for people

- **Products and manual items can be edited:** name, icon, "always keep at home",
  section. Editing uses the same sheet as adding. It doesn't touch the "at home" and
  "to buy" flags or the place in the shopping list. In a new section the product goes
  last.
- **A swipe opens Edit and Delete buttons**, like in Mail. Only one row can be open; a
  tap anywhere else closes it. On desktop, a pencil and a cross on hover.
- **No duplicates:** a product with the same name isn't added twice — the field turns
  red, shakes and says which section it's already in. Case and extra spaces don't matter.
  Same for the shopping list.
- **Tabs switch instantly,** without flicker, and each keeps its own scroll.
- **Other members' changes** show up right away, without refetching the whole home.
- A product that's out is marked with a solid red dot; buttons are a bit more compact.
- On desktop, the "Always keep at home" checkbox toggles on the first click again.

## What changed in the code

- Structure by Feature-Sliced Design — [decision 0011](../decisions/0011-feature-sliced-design.md).
  Layer boundaries are checked by the `fsdBoundaries` test.
- Styles split by layer, sizes in `rem` from the scales in `tokens.css` —
  [decision 0012](../decisions/0012-css-by-layer-rem.md).
- Realtime puts rows straight into the cache, Home and Shopping stay mounted —
  [decision 0013](../decisions/0013-realtime-into-cache-kept-tabs.md).
- Migration `0009`: a product's `updated_at` changes only with its flags; indexes on
  foreign keys.
- Security headers on Vercel (CSP, no framing etc.) and a test that the inline theme
  script's hash matches the CSP.
