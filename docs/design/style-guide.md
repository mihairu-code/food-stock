# Style guide — Pantry / «Домашние запасы»

Версия 1 · направление: бумажный 2D-интерфейс для домашнего учёта продуктов.

## Идея

Интерфейс похож на аккуратную настольную карточку-запасник: разделы — листы, продукт — строка в карточке, статус — заметная подпись или штамп. Бумажная фактура остаётся тихим фоном; название и состояние продукта всегда читаются быстрее декоративных деталей.

**Характер:** домашний, предметный, спокойный, собранный. Не ретро-скрапбук, не детская иллюстрация и не фотореалистичная бумага.

## Цвета

| Токен | Цвет | Использование |
|---|---|---|
| `paper-base` | `#F4EEDF` | Фон приложения — тёплая небелёная бумага |
| `paper-sheet` | `#FFFCF3` | Поля ввода и нижние листы; фон списков совпадает с фоном приложения |
| `paper-shadow` | `#E9E0CE` | Короткая смещённая тень листа, без объёмного blur |
| `ink` | `#30352E` | Основной текст и контуры |
| `ink-muted` | `#66675D` | Подписи и вторичная информация |
| `rule` | `#D8CFBB` | Линии, разделители, перфорация |
| `sage` | `#4F6848` | Основное действие, выбранная навигация, наличие |
| `sage-soft` | `#E8EDDF` | Мягкая заливка активного состояния |
| `tomato` | `#9B3D30` | Закончившийся базовый продукт, удаление, ошибки |
| `tomato-soft` | `#F7E8DF` | Подложка статуса «Закончилось» |
| `honey` | `#7A5C1A` | Разовые позиции, подсказка, необязательный акцент |
| `honey-soft` | `#F5EDD6` | Бумажная заметка/пояснение |

Красный — только для нехватки/удаления; зелёный — наличие/основное действие; охра — разовый характер/заметки. Текст статуса всегда подписан, цвет сам по себе не несёт смысл.

## Материал и форма

- Основная поверхность и фон списков: один и тот же тёплый лист `paper-base` с едва заметным зерном и редкими строками. Не помещать список на отдельную белую плашку.
- Разделы отделяются тонким контуром `1px`, отступом и редкими строками; короткая смещённая тень допустима у отдельных листов вне основного списка.
- Разделители в списках: тонкие сплошные или редкие штриховые линии (`1px`, `rule`).
- Бумажные элементы остаются 2D: без тяжёлого размытия, градиентных бликов, 3D-наклона и фотореалистичной текстуры.
- Статусы наличия выглядят как минимальные тетрадные чекбоксы: тонкий квадрат с галочкой для «Есть», квадрат с коротким тире для «Закончилось» и короткая подпись. Не использовать большой штамп, капс, наклон или заливку статуса.
- Модальные листы: плотный непрозрачный лист, тонкий верхний контур, затемнение фона. Не имитировать физический drag, если это мешает управлению с клавиатуры.

## Типографика

- Заголовки экранов и разделов: системная серифная гарнитура (например, Georgia), вес 400–600.
- Названия продуктов, подписи, кнопки: системная sans-serif, вес 400–700.
- Размеры для мобильной ширины: заголовок 24–28px; название продукта 14–16px; основной текст 14–16px; подпись 12–13px; вспомогательная пометка не меньше 11px.
- Использовать sentence case. Не писать продуктовые статусы только заглавными буквами; капс допустим лишь для короткого декоративного штампа.
- Для интерфейса — русский язык. Короткие английские имена токенов допустимы в CSS.

## Иконки и иллюстрации

- Продуктовые символы: эмодзи в нейтральной бумажной подложке или простые одноцветные линейные пиктограммы.
- Иконки действий: единый тонкий line-icon набор; одна активная кнопка не должна содержать emoji вместо системной иконки.
- Не использовать фотографии продуктов в списках MVP: они создают лишний визуальный шум и задерживают ввод.
- Эмодзи — декоративная помощь, а не обязательная информация; название продукта всегда остаётся видимым.

## Компоненты

### Раздел дома

Бумажная карточка с названием, эмодзи/пиктограммой и счётчиком. Заголовок нажимается для сворачивания. Добавление и переименование доступны без скрытых hover-only действий. Удаление раздела требует подтверждения каскадного удаления.

### Строка продукта

Слева иконка, по центру название и тип (`Базовый продукт` или `Разово`), справа два независимых действия: минимальный тетрадный статус наличия `Есть ↔ Закончилось` и компактная кнопка `＋ В покупки` / `✓ В списке`. Добавление в покупки само по себе не меняет наличие. Разовая запись удаляется свайпом; на клавиатуре и скринридере доступна кнопка/меню «Удалить».

### Строка покупок

Название, источник и отдельная подпись наличия для связанной позиции (`Есть дома` / `Закончилось`), действие «Куплено». Поэтому в покупках может быть продукт, который ещё есть дома. Для связанной позиции покупка восстанавливает наличие. Несвязанная ручная позиция показывает `Не в запасах`; после покупки открывается нижний лист с выбором раздела и чекбоксом «Сделать базовым для этого списка».

### Кнопки

- Primary: заливка `sage`, тёмная тонкая обводка `ink`, текст светлый; короткая тень листа.
- Secondary: `paper-sheet`, тонкий контур `rule`/`ink`.
- Destructive: текст/контур `tomato`; необратимое удаление раздела подтверждается отдельно.
- Высота тач-цели не менее `44px`; кликабельный текст не ниже 14px.
- Нижняя навигация компактна по внешним отступам; каждая вкладка сохраняет минимум `44px` высоты для удобного нажатия.

### Bottom sheet

Для подтверждения покупки и назначения раздела. Поле выбора выше необязательного чекбокса. Основной CTA один: «Добавить домой». Название купленного продукта отображается в заголовке/описании.

## Состояния и микрокопи

- Наличие: `Есть`.
- Базовый продукт стал закончившимся: автоматическая строка в покупках, если её ещё нет. У разового продукта «Закончилось» не добавляет покупку автоматически.
- Ручное намерение купить связанный продукт сохраняется независимо от наличия.
- При возвращении в наличие автоматически созданная строка убирается, явно добавленная пользователем остаётся.
- Разовый продукт: `Разово`; не создаёт покупку при удалении/исчерпании.
- После покупки базового: `Молоко снова есть дома`.
- После разовой покупки без повышения до базового: `Добавлено один раз в «Шкаф»`.
- При ошибке сохранения показывать понятное сообщение и возможность повторить; не скрывать несохранённое состояние.
- При удалении продукта не использовать термин «архив» или обещание восстановления: удаление окончательное.

## Доступность и адаптивность

- Mobile-first, ширина от 320px; основные сценарии рассчитаны на одну руку.
- Контраст текста и фона целевой не ниже WCAG AA. Проверить фактические пары текста/заливки перед релизом.
- Никакая информация о наличии не передаётся только цветом; есть текст и/или значок.
- Клавиатурная навигация и видимый фокус; диалоги имеют заголовок, `aria-modal`, корректный возврат фокуса.
- У свайпа есть альтернативное действие удаления.
- Учитывать `prefers-reduced-motion`; не делать анимацию обязательной для понимания.
- Фактура может быть отключена/упрощена для экономии рендеринга и лучшего контраста.

## Тёмная тема

Тёмная тема сохраняет ощущение бумаги: использовать угольную/графитовую бумагу и тёплые светлые чернила, а не чёрный фон с чисто белым текстом. Фон приложения, списков и разделов остаётся одним и тем же; тонкие строки и зерно становятся едва светлее фона. Светлая тема остаётся прежней.

| Токен | Светлая | Тёмная |
|---|---|---|
| `paper-base` | `#F4EEDF` | `#242722` |
| `paper-sheet` | `#FFFCF3` | `#2D302A` |
| `paper-shadow` | `#E9E0CE` | `#191C18` |
| `ink` | `#30352E` | `#F1ECDF` |
| `ink-muted` | `#66675D` | `#BCB7A9` |
| `rule` | `#D8CFBB` | `#4C4D43` |
| `sage` | `#4F6848` | `#AFC69A` |
| `sage-soft` | `#E8EDDF` | `#354337` |
| `tomato` | `#9B3D30` | `#EF9D88` |
| `tomato-soft` | `#F7E8DF` | `#4B312C` |
| `honey` | `#7A5C1A` | `#E5C06A` |
| `honey-soft` | `#F5EDD6` | `#403822` |

- Кнопка в тёмной теме получает тёмный текст на светлом sage-заливке; не оставлять белый текст на светлом акценте.
- Чекбокс «Есть» остаётся sage, «Закончилось» — tomato; меняются только контрастные пары, форма маркера остаётся одинаковой.
- Фон списка не становится отдельной более светлой карточкой: использовать `paper-base` и общий текстурный паттерн приложения.
- Поля и нижние листы могут использовать `paper-sheet`, чтобы отделяться от основного фона.
- В настройках пользователь может переключить светлую/тёмную тему. Выбор применяется ко всем экранам и сохраняется между запусками. Для первой реализации достаточно двух явных режимов; автоматический системный режим можно добавить отдельно.
- Перед реализацией проверить пары текста/фона и цвета статусов на контраст WCAG AA в обеих темах.

## Не делать

- Не добавлять рулоны скотча, рваные края или «рукописный» шрифт к каждой строке: бумажная тема должна оставаться ясной.
- Не кодировать базовый/разовый тип только разными цветами.
- Не добавлять количества, сроки годности, рецепты, поиск по каталогу или сканер чеков без отдельного решения о расширении MVP.
- Не использовать длинные тени, градиенты, стеклянные поверхности и перегруженные декоративные рамки.
